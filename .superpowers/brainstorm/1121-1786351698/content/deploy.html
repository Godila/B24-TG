Структура docker-compose

4 сервиса
services:
  app          # FastAPI + Telethon + outbox-воркер (один контейнер)
  postgres     # БД
  redis        # очередь outbox + кэш throttler + rate-limit
  nginx        # TLS-терминация + reverse proxy + статика

Два режима запуска Telethon-сессии

Первый вход (разовый)

Запускаем CLI-команду на сервере:

docker compose run --rm app python -m app.auth_login

Вводим код из TG → пароль 2FA → .session сохраняется в volume.

⚠ Только один раз. Далее сессия живёт в volume.

Боевая работа

Telethon стартует как часть app, читает готовый .session:

docker compose up -d

FastAPI + Telethon + outbox-воркер — один процесс. Restart: always.

Healthcheck → Nginx 503 если сессия упала.

Мониторинг и алерты

📡 Health endpoint /health: статус Telethon-сессии, БД, Redis → Nginx/uptime-чекам

🚨 Sentry — все исключения приложения

📢 Критичные алерты админу (в Telegram или на email):

• сессия упала / .session невалиден

• FloodWait > 1 часа

• аккаунт в бане (UserBanned/SpamBot)

• OAuth Bitrix24 требует re-authorize
