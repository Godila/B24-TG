Поток входящего сообщения

Клиент пишет в Telegram → появляется в Bitrix24
1. Клиент пишет в TG
2. Telethon (TelegramProvider) получает событие NewMessage
3. Сохраняем в Postgres (messages + dialogs)
4. Chat Service решает: новый диалог?
   ├─ ДА → Bitrix24Sync создаёт Контакт + Сделку
   │       привязывает TG chatId ↔ CRM dealId
   └─ НЕТ → находим существующую сделку
5. Bitrix24Sync пишет текст в timeline сделки (crm.timeline.comment)
6. Уведомление менеджеру (чат-бот Bitrix24 / push в Web UI)
7. Менеджер видит в Web UI / виджете карточки

Ключевые абстракции:
• MessengerProvider — интерфейс: send_message(), on_message(), on_status(). Telegram и MAX реализуют его.
• Bitrix24Sync — отвечает только за CRM: создание сущностей, timeline, вебхуки.
• TaskQueue — throttle отправки (защита от бана) + retry при ошибках.
