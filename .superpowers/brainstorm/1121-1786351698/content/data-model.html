Ключевые решения

1. contacts.tg_user_id — связь через Telegram ID, не номер телефона. В Telegram ID постоянный, номер может меняться. Поиск клиента по tg_user_id → быстрый lookup.

2. dialogs — связующее звено. Один контакт может иметь несколько диалогов (через TG, позже через MAX). Диалог привязан к crm_deal_id — это и есть «якорь» к CRM.

3. messages.timeline_comment_id — храним ID комментария в таймлайне Bitrix24. Позволяет обновлять/удалять комментарий при редактировании сообщения и избежать дублей.

4. outbox отделён от messages. Очередь отправки живёт отдельно — так throttle-воркер читает только pending-задачи, не сканируя всю переписку. Защита от бана изолирована.

5. messenger enum уже сейчас. Хотя работаем только с TG, поле готово под MAX — не придётся мигрировать схему позже.
