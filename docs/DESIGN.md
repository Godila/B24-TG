# DESIGN.md — дизайн-система «ЧатМост» (источник истины)

> Нотация: Google design-doc — Контекст → Линза → Цели/Не-цели → Дизайн
> (токены, компоненты, экраны, CJM, a11y-пол) → Альтернативы → Журнал
> решений + Реестр задач. Изменения дизайна начинать с правки этого файла,
> затем эталонного файла компонента.

## 1. Контекст и охват

Продукт «ЧатМост» — мост между личными мессенджерами (Telegram, MAX) и
Битрикс24. Три поверхности, все — статические файлы без сборки (Alpine.js
vendored), живут в iframe внутри портала Битрикс24:

| Поверхность | Файлы | Вход | Основная роль |
|---|---|---|---|
| Виджет чата в сделке | `static/placement.html` + `app.js` + `style.css` | вкладка CRM_DEAL_DETAIL_TAB | менеджер |
| Оболочка левого меню | `static/app-shell.html` | единственный пункт LEFT_MENU → `/placement/app` | все |
| «Чаты» (общий мессенджер) | `static/inbox.html` + `inbox.js` + `inbox.css` (поверх style.css) | вкладка оболочки / прямая ссылка `/placement/chats` | менеджер / supervisor |
| Панель управления | `static/admin.html` (inline CSS) + `admin/channel-connect.js` | вкладка оболочки / прямая ссылка `/placement/admin` | менеджер / supervisor |

Пользователи: менеджеры продаж (ежедневный поток сообщений) и руководитель
(supervisor: надзор + настройки). Ограничения среды: без CDN (сети РФ),
без сборки, iframe Битрикс24 (кука SameSite=none, светлая тема портала),
обновление данных polling 3 с.

## 2. Линза дизайна (выбрана)

**«Спокойный рабочий инструмент внутри Битрикс24»**: утилитарная
сдержанность, ноль декора ради декора, максимум плотности информации при
сохранении «дыхания». Одна дизайнерская ставка (signature) — **возраст
ожидания в «Чатах»**: строка неотвеченного диалога показывает, сколько
клиент ждёт ответа («24 мин»), с нарастанием тона от жёлтого к красному
за час. Бренд-минимум — марка «⇄» на градиенте в панели управления.

Принципы:

1. **Преемственность с Битрикс24** — страница читается как часть портала,
   не как чужой сайт; система UI не спорит с хостом.
2. **Узнавание вместо припоминания** — состояние видно без открытия:
   секция «Ожидают ответа», превью последнего сообщения, счётчики.
3. **Минимум усилий** — непрочитанные гасятся при открытии; первый
   неотвеченный диалог открывается сам; отправка с оптимистичным UI.
4. **Честные состояния** — пустой экран и ошибка — это направление
   («что делать»), не констатация и не извинение.
5. **A11y-пол обязателен** — настоящие `<button>`/`<input>`, видимый
   `:focus-visible`, контраст WCAG AA (≥4.5:1 для мелкого текста),
   `aria-label` для иконочных контролов, `prefers-reduced-motion`.
6. **Сдержанность** — один signature-элемент на продукт; всё остальное —
   тихая дисциплина токенов.
7. **Словарь един** — одно действие называется одинаково везде; статусы
   каналов — один словарь (подключён/офлайн/заблокирован/ожидание/ошибка).

## 3. Цели / Не-цели

**Цели:** единые токены, типографика и компоненты на всех трёх
поверхностях; WCAG AA на новых поверхностях; петля CJM менеджера без
«молчаливых» состояний; этот файл — единственный источник истины +
реестр UX-задач с приоритетами.

**Не-цели (v1):** ребрендинг; тёмная тема Битрикс24 (зафиксировано как
недомолвка iframe, задача после v2); извлечение общего CSS/JS-модуля
(без сборки паттерны копируются с маркером «синхронизировано с …»);
анимации сверх необходимых; отдельная мобильная вёрстка (min-width
контейнера B24).

## 4. Дизайн-система

### 4.1 Токены (канон, v1)

| Токен | Значение | Комментарий |
|---|---|---|
| `--bg` | `#f2f4f8` | фон страницы |
| `--card` | `#ffffff` | поверхность карточки |
| `--border` | `#dfe3ea` | линии/рамки |
| `--text` | `#1c2733` | основной текст |
| `--muted` | `#66707d` | вторичный текст (AA 5.3:1 на белом) |
| `--accent` / `--accent-dark` | `#2f6fed` / `#1f57c7` | действия, активные состояния |
| `--danger` | `#b3352f` | деструктивное |
| ok / warn / err / wait | пары фон+текст: `#e6f6e6/#1d7a35`, `#fdf3d8/#8a6d1a`, `#fde8e8/#b3352f`, `#eef4fd/#2a5fa8` | статусные бейджи/чипы |
| канал TG | `#e5f1fb` / `#1c6fb3` | бейдж/иконка |
| канал MAX | `#f0e9fd` / `#6a3db8` | бейдж/иконка |

Правила: контраст мелкого текста (≤14px) ≥ 4.5:1 — токен `--meta
#8a94a6` в `style.css` НЕ канонический, миграция задачей UX-01. Радиусы:
8 контролы, 12–14 карточки, 999 пилюли. Тень карточек:
`0 1px 3px rgba(20,30,50,.05)`.

Типографика: системный стек `-apple-system, "Segoe UI", Roboto,
"Helvetica Neue", Arial, sans-serif`; база 14px / 1.45; шкала — 11px
(uppercase-метки секций), 12px (метаданные), 13–14px (текст), ~17px (h2
страницы), ~23px (h1). Заголовки двух уровней: h2 страницы (1.05rem) и
`section-title` плотного списка (11px uppercase muted).

Иконки каналов: текстовые бейджи «TG»/«MAX» — в плотных списках;
эмодзи-иконки (✈️ / 🅜) — только в карточках настроек.

### 4.2 Компоненты (эталоны)

| Компонент | Эталон | Правило |
|---|---|---|
| Оболочка-вкладки `app-shell.html` | сам файл | единственный вход левого меню: сегмент-вкладки «Чаты»/«Панель» + ленивые iframe (изоляция CSS/JS поверхностей); активная вкладка в `#hash` |
| Кнопка `.btn` (+`--ghost`/`--danger`/`--sm`) | `admin.html` | все интерактивные — настоящие `<button type>`; primary синий, ghost для вторичных, danger для деструктива; `:focus-visible` 2px accent |

| Чип с действием `.chip` + `.chip-x` | `admin.html` | `chip-x` с `aria-label` |
| Аватар-инициалы `.m-avatar` (38px, круг) | `admin.html` | инициалы из ≤2 слов; миграция в «Чаты» — UX-06 |
| Карточка `.channel-card` / `.settings-card` / `.manager-row` | `admin.html` | белая поверхность + border + тень токена |
| Сегмент-контрол `.segment` | `admin.html` | взаимоисключающий выбор режима |
| Строка диалога `.dialog-row` | `inbox.html` | доработки UX-02/05/06/07 |
| Пузырь сообщения `.bubble-in/out` | `style.css` | max-width 72%, статусы ⏳✓⚠ |
| Пустое состояние | текст-эталон в UX-04 | приглашение к действию |

### 4.3 Экраны: отклонения от канона

- **Панель управления** — унифицирована 2026-08-17 (см. журнал). Остаток:
  `alert()` на ошибках действий → UX-09.
- **«Чаты»** — новая поверхность; известные отклонения: UX-01…UX-07,
  UX-10, UX-11 (реестр ниже).
- **Виджет сделки** — прод, «не трогаем» без причины; отклонения:
  `--meta` контраст (UX-01, общая с «Чатами»), `<title>` «Bitrix-TG Чат»
  вместо «ЧатМост» (UX-08).

| Стадия | Состояние | Гэп → задача |
|---|---|---|
| 1. Триггер (клиент написал) | вне открытой вкладки не сигнализируется нигде | UX-10 (title+звук), v2: бот |
| 2. Вход (меню → «Чаты») | ✅ | — |

| 4. Чтение | авто-открытие первого неотвеченного; forced-scroll при чтении истории | UX-05 |

### 4.5 A11y-пол (обязательный минимум для любой новой поверхности)

1. Интерактив — только `<button>`/`<input>`/`<a>`; кликабельные div'ы
   запрещены (нарушение в «Чатах» — UX-02).
2. Глобально видимый `:focus-visible` (2px accent, offset 2px).
3. Контраст мелкого текста ≥ 4.5:1; проверять токены, не «на глаз».
4. `aria-label` всем иконочным/безтекстовым контролам; `aria-live` для
   входящих сообщений (задача в UX-02).
5. `prefers-reduced-motion` — переходы только в no-preference.
6. Пустые состояния и ошибки — словами-действиями, не заглушками.

## 6. Альтернативы, рассмотренные и отвергнутые

- **Канон токенов из `style.css` (виджета)** — отвергнуто: его
  `--meta #8a94a6` не проходит AA, нет статусных пар; набор панели
  управления зрелее (бейджи/чипы/аватары/кнопки уже там) — за него.
- **Общий CSS/JS-модуль для чат-панели** — отложено до появления
  JS-тестов: рефакторинг прод-виджета без страховки дороже дублирования;
  копии помечены «синхронизировано с app.js».
- **Тёмная тема** — джарринг светлого iframe в тёмном портале признан,
  но вынесен за v1 (нужна стратегия `prefers-color-scheme` по всем
  токенам).
- **Signature-варианты** (красная лента очереди, сводка в шапке) —
  выбран возраст ожидания: единственный вариант, который одновременно
  закрывает CJM-стадию «приоритизация».

## 7. Журнал решений

- **2026-08-17** — UX-аудит «Чатов» и панели на живом стенде (менеджер +
  supervisor, 1600/1280/780px, DOM-снимок): выбрана линза «спокойный
  рабочий инструмент», signature = возраст ожидания; канон токенов =
  набор панели управления; панель унифицирована (кнопки `.btn` в
  `channel-connect.js`, системный шрифтостек, кегль 14, `:focus-visible`,
  `prefers-reduced-motion`, `aria-label` чипов); заведён реестр UX-01…11.
- **2026-08-17 (волна 2)** — весь реестр UX-01…11 исполнен и проверен
  вживую. Ключевые решения волны: UTC-нормализация через pydantic
  `field_validator` в DTO (дев=прод, тесты `test_schemas_utc.py`);
  supervisor-фильтр — клиентскими чипами (не select: `<template>` внутри
  `<select>` невалиден для HTML-парсера); scroll-anchor с пилюлей
  «↓ Новые сообщения» через sticky-последний-элемент ленты; звук —
  WebAudio-осциллятор без аудиофайлов (нечему грузиться в офлайн-iframe).
- **2026-08-17 (волна 3)** — живая проверка опровергла мульти-биндинги:
  B24 рендерит ОДИН пункт LEFT_MENU на приложение (биндинг «Чаты»
  существовал в placement.get, пункт в меню не появился; подтверждено
  документацией placements). Решение: оболочка `/placement/app`
  (`app-shell.html`) — вкладки «Чаты»/«Панель» с ленивыми iframe на
  существующие страницы (полная изоляция CSS/JS, нулевой рефакторинг
  поверхностей); `bind_chats_placement.py` теперь приводит меню к виду
  «единственный LEFT_MENU = /placement/app» (legacy-хендлеры отвязывает).
  Отвергнуто: GROUP_NAME (не решает лимит для LEFT_MENU) и второе
  приложение (операционный overhead ради одного пункта).
