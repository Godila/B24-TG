# AGENTS.md — ЧатМост

## Методология
feature-dev (дискавери → архитектура → реализация → ревью) + Superpowers
(TDD, systematic-debugging, verification-before-completion).
Ponytail — режим исполнения: минимальный работающий код. Дополняет, не заменяет.

## Лестница (при выборе решения и написании кода)
1. Нужно ли вообще? (YAGNI)  2. Уже есть в кодовой базе?  3. stdlib?
4. Нативная фича платформы?  5. Установленная зависимость?  6. Одной строкой?
7. Только потом — минимальный рабочий код.

## Точки входа в воркфлоу
- feature-dev Phase 4: лестница = тай-брейкер при синтезе архитектур.
- feature-dev Phase 5: перед кодом — /ponytail full. Вывод: `[код] → skipped: X, add when Y`.
- feature-dev Phase 6: после 3 reviewer-агентов — /ponytail-review по диффу.
- Баги: root cause + grep всех callers.
- Milestone: /ponytail-audit (one-shot), находки — в бэклог.

## Долг
Осознанный срез угла: `# ponytail: <потолок>, <условие апгрейда>`. Без триггера = гнильё.
Периодически /ponytail-debt — сверка с v2-бэклогом.

## Когда НЕ лениться (специфика проекта)
- Fail-closed парсинг чужих данных: push_parser (own_user_id=None → skip).
- Границы доверия: B24 webhook, OAuth/токены, media upload.
- Outbox/retry: ничего, что теряет сообщения.
- Миграции БД.
- Тесты: src/ — полный pytest-стандарт (протоколы реверс-инжинирятся,
  регресс-сеть критична); scripts/ и спайки — один assert-чек.
- Докстринги контрактов (протокол, provider API) — остаются; пересказ кода — нет.

## Память agentmemory
SessionStart-хук ZCode подкачивает сводку недавних записей. Факт-поиск по ходу — MCP `memory_recall`. Значимый инсайт (живая грабля протокола, корневая причина, правило юзера) — `memory_save` СРАЗУ в момент находки, не копить на конец сессии (авто-компакт не спрашивает); закрытие сессии / compact — досбор хвостов. project=bitrix-tg. Файловая память (MEMORY.md) — источник правды, agentmemory — семантический слой поверх.

## Формат
Код → максимум три строки пояснений. Отчёты по явному запросу — полностью.
